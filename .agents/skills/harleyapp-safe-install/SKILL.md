# HarleyApp 安全覆盖安装

## 核心规则

必须把设备中现有 HarleyApp 的用户数据安全放在第一位。

- **不得主动卸载 App，只能覆盖安装。** 始终使用带 `-r` 的 ADB 覆盖安装方式，例如 `adb -s <设备序列号> install --no-streaming -r <APK路径>`。
- 禁止执行 `adb uninstall`、`pm uninstall`、`pm uninstall --user`、`pm clear`，也禁止通过系统设置、脚本或其他工具卸载应用或清除应用数据。
- 禁止采用“先卸载、再安装”来解决签名冲突、版本降级或安装失败。
- 本 Skill 的授权范围永远不包含卸载或清除数据。即使用户说“尽快装上”“想办法处理”，也不得推定为卸载授权。
- 不得主动把卸载重装列为常规建议。用户若另行主动提出卸载要求，立即停止本 Skill 的安装流程，先单独说明数据丢失风险并等待明确确认，不能在当前流程中顺带执行。
- 如果覆盖安装无法继续，停止在数据仍安全的状态，向用户报告原始错误及可选方案；不得自行用破坏性操作绕过错误。

## 操作流程

### 1. 确认当前状态

1. 先运行 `git status --short`，记录现有未提交内容，只处理当前任务范围内的文件。
2. 不得修改或还原 `sdkconfig`，无论它是否已提交或已有本地改动。
3. 从当前 Gradle 配置或 Manifest 确认实际 `applicationId`，不得凭记忆猜测包名。
4. 使用 `adb devices -l` 确认目标设备。存在多台设备时必须指定 `-s <设备序列号>`，不能随机选择。
5. 安装前查询设备上的包和版本信息，用于安装后的对比；查询失败时如实说明，不得声称数据已验证。

### 2. 构建与静态验证

按任务风险选择最小充分验证。完整交付默认运行：

```powershell
.\gradlew.bat :app:testDebugUnitTest :app:lintDebug :app:assembleDebug --no-daemon --no-configuration-cache
```

构建失败时区分源码错误、环境错误和依赖错误，不得为了让安装继续而跳过关键失败并宣称成功。

### 3. 仅执行覆盖安装

确认 APK 路径、目标设备和包名后，只能执行保留现有应用数据的覆盖安装：

```powershell
adb -s <设备序列号> install --no-streaming -r <APK绝对路径>
```

`-r` 是强制参数。即使设备当前没有安装该包，也保持使用同一条安全命令，不另外引入卸载步骤。

以下情况必须停止并报告，不得卸载 App：

- `INSTALL_FAILED_UPDATE_INCOMPATIBLE`：优先检查构建所用签名是否与已安装版本一致。
- `INSTALL_FAILED_VERSION_DOWNGRADE`：优先构建更高 `versionCode` 的 APK；是否使用降级参数必须先取得用户明确同意。
- 空间不足、设备离线、授权失败或 APK 无效：处理对应根因后重新覆盖安装。
- 任何只能通过卸载才能继续的情况：说明当前无法在本 Skill 的数据保护边界内继续，保留现状，并等待同签名 APK、更高 `versionCode` 等无损条件；不得主动建议卸载。

### 4. 分层验证并如实报告

1. ADB 返回 `Success` 只证明系统接受了覆盖安装，不等于界面、功能或历史数据已经验证。
2. 安装后重新查询包版本，确认设备上的版本与目标 APK 一致。
3. 只有实际启动成功后，才能报告“启动验证通过”。
4. 只有实际检查到原有记录、设置或文件仍存在后，才能报告“应用数据保留已验证”。
5. 将单元测试、Lint、APK 构建、覆盖安装、启动检查、界面检查和数据保留检查分别列出，不得把其中一项成功扩大为全部成功。

## 安装失败时的回复要求

必须给出：

- 执行的覆盖安装命令类型，但隐藏任何敏感信息。
- ADB 的原始错误码或关键英文错误信息。
- 当前数据仍未被删除的确认。
- 不丢数据的下一步方案；不得把卸载重装包装成推荐方案。

任何日志内容使用英文；面向用户的说明和代码备注使用中文。
